## 3. Dự đoán và thực tế

1. **hard_eval**: Đoán BoW tụt F1 ~0.5–0.6 trên 50 case khó → thực tế 0.286, tụt nặng hơn rất nhiều. 50 case khó cố tình né từ khoá và viết giọng tự nhiên, BoW hoàn toàn bó tay.

2. **emb_tricky**: Đoán Embedding đúng 5–6/6 → thực tế cả BoW lẫn Embedding đều sai 1 case. Embedding không phải bất khả chiến bại.

3. **ml_f1**: Đoán F1 ~0.92 → thực tế 0.851. LogReg trên BoW yếu hơn tưởng tượng, recall thấp vì spam né từ khoá.

## 4. Phân tích 50 case khó

BoW + LogReg tụt nhiều nhất: F1 từ 0.857 → 0.286. MLP cũng: 0.919 → 0.410. Nhóm khó nhất với BoW: natural_spam và obfuscation.

- Case "Hey bro ur phone bill is overdue...": spam giọng bạn bè, không có từ khoá spam → BoW đoán ham.
- Case "D0nt m1ss th1s d3al": thay chữ bằng số, BoW không nhận ra → đoán ham.

Embedding giữ F1 ~0.750, LLM giữ ~0.949. Prompt phòng thủ (4d) tăng F1 lên 0.966.

## 5. Thử thách cá nhân

Đề #6: Sửa prompt để LLM trả JSON `{"label": ..., "reason": ...}`, so sánh token/chi phí.

Viết `build_json_prompt` + `parse_json_label`. Chạy trên 10 tin SUB: cả hai bản F1 ~1.0. JSON tốn gấp 1.4x token (768 vs 531). JSON cho thêm lý do nhưng không tăng accuracy. Với task đơn giản, bản 1 từ hiệu quả hơn. JSON đáng khi cần audit trail.

## 6. Phương án cho sản phẩm thật

Chọn **Emb + LogReg**: F1=0.956, p95=28.8ms (dưới SLA 50ms), chi phí $0/tin.

Nếu cần cao hơn: router — Emb+LogReg lọc trước, tin có p ∈ [0.3, 0.7] (~10–15%) chuyển cho LLM. Chi phí giảm ~7–8 lần so với LLM toàn bộ ($2,700/tháng).
